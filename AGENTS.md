## What this product is

SkillFlow is a mastery-first learning app. A learner follows a skill, opens a stage of real external resources, and passes an explain-back before the stage is recorded. Version 1 grades a real stage one idea at a time. There is no quiz. A learner can also bring their own resource and get an explain-back gate prompt for it (Version 2 preview). Thirty paths are free, including every stage, so finishing a path can earn the certificate. The next stage opens only after the explain-back on the current one is passed.

There are no comments, likes, or view counts. Premium is one Stripe subscription. It opens the niches outside the thirty free paths, and it lets the learner appear on the learner map. The map itself, nearby events, the thirty paths, and explain-back stay free.

## Free paths and Premium niches

Thirty paths are free and available to everyone. The list is `FREE_PATH_SLUGS` in `lib/niches/tiers.ts`. All thirty have catalogs. Do not invent catalogs for Premium niches.

A stage is structurally open when the skill is `AVAILABLE`, the offer is `FREE`, and the stage is not monetized. `LOCKED_TAIL` is 0, so every stage on a free path is open. The real description and resources are sent. A learner who passes every stage can open the certificate.

On top of that, the next stage stays shut for this learner until every earlier open stage has a passed explain-back. A stage they already passed stays open. That check is personal: it lives in `loadCatalog`, `getLesson`, the milestone, and the explain-back write. It is not inside `"use cache"`. The sentence is "Pass the previous stage to open this one." A stage waiting on that pass still shows its title, photo, and description, with a lock.

Every slug outside that list is Premium: `AVAILABLE`, `MONETIZED`, and zero stages. A free account sees Premium and cannot open the roadmap. A subscriber, and an admin, can open it and follow it. There are still no stages. Do not invent resources. The label is the lock until Stripe marks the subscription active or trialing.

## How to load a catalog

The importer is server-only. Dry-run first. Apply only after the dry-run touches that skill alone.

```bash
npx tsx scripts/verify-catalog.ts <slug>
npx tsx --conditions=react-server scripts/import-catalog.ts <slug>
npx tsx --conditions=react-server scripts/import-catalog.ts <slug> --apply
```

A second dry-run should print "Nothing to change." `--from-db` checks rows already stored and can mark a dead link `UNAVAILABLE`. It writes `content/catalog/_review/<file>.from-db.md`. Use it only when asked. A 403 or a bot challenge is "needs manual check", not a failure, and is not a reason to replace the link.

Do not run `npx prisma db seed`. The seed rewrites every niche. Admin accounts come from `SEED_ADMIN_EMAILS` (comma-separated) and `SEED_ADMIN_PASSWORD` (12 characters or more) in `.env`; without both it skips admins. An existing account is only promoted to `ADMIN`, and its password is never reset. The seed refuses to run when `NODE_ENV` is production unless `ALLOW_PROD_SEED=yes`, which is meant for one run on an empty database. After a catalog apply, set status, offer, and `isFlagship` with a targeted Prisma update. `seedStatus` returns `AVAILABLE`. `seedOffer` returns `FREE` when the slug is in `FREE_PATH_SLUGS`, and `MONETIZED` otherwise. The seed imports the live catalogs, including Animation, IoT, Screenwriting, Graphic Design, SEO, AI Tools, Cybersecurity, Digital Marketing, Personal Finance, Public Speaking, Sound Design, Nutrition, Psychology, Podcasting, Guitar, Chess, Art & Painting, Photography, Emergency Preparedness, Badminton, Relationships, Socializing, Interior Design, Freelancing, and Travel Planning. The dead links named above stay in those files until a working page is chosen.

The ideas are written from that stage’s resources the first time the gate opens, and again when those resources change. Every key point is kept. A page the site blocks is skipped. With no model key, the questions already in the catalog stay. ## Stack facts that are easy to get wrong

- Next.js 16.3.4, React 19.2.8, Tailwind v4, Prisma 6.19.3, NextAuth v5 beta.32. `trustHost: true`. Sessions are JWT. Credentials needs JWT. Do not describe database sessions.
- Google sign-in is live when `AUTH_GOOGLE_ID` and `AUTH_GOOGLE_SECRET` are set (`googleAuthEnabled()` in `lib/google-auth.ts`); without them the provider and the buttons are left out. Login and signup show "Continue with Google" / "Sign up with Google" (`components/forms/GoogleButton.tsx`), which lands on `/auth/continue`: onboarding for a new learner, Home otherwise. The `signIn` callback only accepts a Google profile with `email_verified`. Linking is never by email match alone: a signed-out Google sign-in whose email already has a password account is refused (`OAuthAccountNotLinked`, explained on `/login?error=`); the learner logs in with the password and connects Google from Settings → Sign-in, which links to the signed-in user. The `linkAccount` event sets `emailVerified`, and moves an unverified account email to the verified Gmail when no other account uses it. Disconnect is refused when the account has no password. Emails are lowercased on signup and login (`normalizeEmail`). Login and signup are static pages, so a deploy needs the Google keys at build time for the buttons to render.
- `cacheComponents` is on in `next.config.ts`. Shared niches, stages, resources, the niche grid, lesson screens, clips, and the submit picker use `use cache` with the `catalog` tag. Merged community lists, a published post, member counts, gaps, the changelog, contributors, and contributor profiles use the `community` tag. The Stripe price label uses `use cache` for an hour and has no tag. Learner-map city totals use the `learner-map` tag. Nominatim city search uses the `geocode` tag. Saved nearby events use the `nearby-events` tag. Text read from a public page for a practice note uses the `practice-source` tag. Landing totals use the `landing-stats` tag (with `catalog`). The global search index uses `catalog` and `community`. The onboarding path picker (`loadFreePaths` in `app/onboarding/page.tsx`) and the landing Clips showcase (`loadLandingReels`) also use the `catalog` tag. The career-fit test, Dopamine Detox, the profile overview, the activity heatmap, the product tour state, and Home's At a glance and For you are personal and stay on the request. The niches page shows 32 cards at a time in the browser, so the page number is not a cache key. Home and the roadmap index reuse a cached teaser of the first rows. Catalog CMS writes and an approved submission call `updateTag`. Progress, streaks, settings, joined state, and “N new” stay on the request. The account menu streams beside that shell. A learner’s own city and map toggle stay on the request.
- `proxy.ts` exports `export const proxy = auth(...)`. `middleware.ts` was deleted. Do not restore it. The proxy only checks that someone is signed in.
- Environment variables are checked once at server start: `instrumentation.ts` calls `validateEnv()` from `lib/env.ts` (Zod) on the Node runtime, never during `next build`. A bad value stops the server, and the error lists variable names only, never values. Rules: `DATABASE_URL` must be `postgresql://`, `AUTH_SECRET` at least 32 characters, the Google pair both or neither, the four Stripe keys all or none, `CRON_SECRET` at least 32 characters when set. In production `CRON_SECRET`, `GEOCODER_USER_AGENT`, and `REDIS_URL` are required, and a missing AI key is a warning. A new environment variable goes into that schema in the same change.
- `GET /api/health` (`app/api/health/route.ts`) runs `SELECT 1` with a 2-second timeout and returns `{ status, db, latencyMs, uptimeSeconds, commit }`: 200 when Postgres answers, 503 when it does not, `no-store`, never prerendered (`connection()`), and no error details. `commit` is `GIT_SHA`, or `dev`.
- Security headers come from `headers()` in `next.config.ts` on every route: `X-Frame-Options: DENY`, `nosniff`, `strict-origin-when-cross-origin`, a `Permissions-Policy` that turns off camera, microphone, geolocation, payment, and topics, and HSTS in production only. `poweredByHeader` is off. The CSP is sent as `Content-Security-Policy-Report-Only`, so it reports and does not block yet. A feature that loads a script, frame, browser `fetch`, or form target from a new host must add that host to the `csp` list in `next.config.ts`, or it will break when the CSP is enforced.
- Redis (`ioredis`, `lib/redis.ts`) is used only for rate limits. It is one lazy shared client with a 500 ms command timeout. With no `REDIS_URL` it returns null and every limit passes, so local development works without it. `docker compose up -d` starts `redis:7-alpine` on 6379 with append-only persistence. The Next cache does not use Redis.
- Rate limits: `rateLimit()` in `lib/rate-limit.ts` is a fixed-window counter (`rl:<name>:<id>:<window>`). Every number lives in `lib/limits.ts`: login 5 per email and 30 per IP every 15 minutes (checked in the Credentials `authorize` in `lib/auth.ts`; a blocked try looks like a wrong password, and it fails closed when Redis errors), sign-up 5 per IP an hour, every AI call 10 a minute and 200 a day per learner (explain-back, recall, notes and practice; a blocked call returns the existing `unavailable` error), and uploads 20 an hour per learner. Everything except login fails open when Redis errors. `clientIp()` trusts the first `X-Forwarded-For` value, so the proxy in front must set that header itself. A new Server Action that calls a model must call `aiAllowed()`, and a new upload action must call `uploadAllowed()`.
- Postgres database name is `skillflow` on localhost:5432. `prisma.config.ts` loads `.env` with dotenv because Prisma 6 does not.
- Migrations: the 29 folders in `prisma/migrations`, `20260923010253_init` to `20261025120000_assistant_knowledge`, all applied. The last one (assistant) runs `CREATE EXTENSION IF NOT EXISTS vector` and creates `KnowledgeChunk` with its HNSW and GIN indexes and the generated `tsv` column, all in raw SQL; Prisma sees `vector` and `tsv` as `Unsupported`, so they are read and written only with `$queryRaw`. Postgres runs on `pgvector/pgvector:pg16-trixie` locally, in production, and in CI: Postgres 16 plus pgvector on the same Debian trixie (glibc 2.41) as the `postgres:16` image the data was created with, so the volume is reused without a collation mismatch (the plain `pg16` tag is bookworm, glibc 2.36, and Postgres warns about the collation version). The last one creates `DetoxAssessment`, `DetoxCheckIn`, and `FocusSession` (all cascade on user delete) and adds `LearnerProfile.showDetoxOnProfile` and `notifyDetox`, every statement `IF NOT EXISTS` or guarded. `20261016120000_product_tour` adds `LearnerProfile.tourCompletedAt`. `20261014120000_notification_settings` adds `LearnerProfile.notifyReviews`, `notifyCommunity`, and `notificationsReadAt` the same way. `20261008190000_contribution_review_unmerge` adds `ContributionReview.unmerge` with `IF NOT EXISTS` (it was in the schema without a migration file). `20261008200000_drop_quiz` drops the three quiz tables and `StageCompletion.quizPassed`. A fresh database from `prisma migrate deploy` matches `schema.prisma` apart from two harmless `updatedAt` defaults. The development database also has two migrations the repo lacks (`20261003062015_learner_location`, `20261003063619_nearby_events`) and an unused `GeocodeCache` table, so write new migrations by hand, keep them additive, and apply them with `migrate deploy`; a generated diff would drop those extras. Do not create a migration unless the schema changes. Do not run `prisma migrate reset`.
- `tsx` top-level await fails under CommonJS. Wrap scripts in `async function main()`. PowerShell has no `&&` and no bash heredoc. It also eats `$disconnect` inside `tsx -e`. Use a temp script, then delete it.
- Full-repo `eslint` still fails on older files. Lint the files you touched. `tsc --noEmit` is the type check. `next build` is a project check and passes. `npm test` runs Vitest. `npm run test:e2e` runs Playwright (Chromium; run `npx playwright install chromium` once first). Its output folders `test-results/` and `playwright-report/` are gitignored, and so are local database dumps (`backup-*.sql`, `*.dump`).
- Do not start a second `npm run dev` if one is already answering on port 3000.
- Known failure strings, left in on purpose: catalog title `fail this save`, settings name `fail this save`, submit title `fail this submit`, review notes `fail this review`, creator title `fail this upload`, Open Source review feedback `fail this merge`.
- Placeholder video id constant is `skillflow-placeholder`. Do not use it to replace a real catalog id.

## UI conventions

Polished in October 2026 (`UI-AUDIT.md`, before and after shots in `docs/ui-audit/`). Keep new screens on these.

- Words in visible copy: **Path** for the ordered list of stages (the sidebar and the index say "Paths"; the route stays `/roadmap`), **niche** for a subject, **stage** for a step, **contribution** in Open Source, **Explain-back** for the check. A pending label ends in the ellipsis character: "Saving…".
- Tokens live in `app/globals.css`. Type: body `--text-body` 0.9375rem, sm 0.875, xs 0.8125, 2xs 0.75, 3xs 0.6875. Motion: `--ease-out`, `--dur-fast` 150ms, `--dur-base` 220ms. `--text-faint` is decoration, never body text. Light borders and `--state-pass` were measured to reach 3:1 and 4.5:1.
- Buttons: `Button` (`components/core/Button.jsx`) takes `variant`, `size`, `pending`, and `pendingLabel`; pending shows a spinner, keeps the width, and sets `aria-busy`. A link that should look like a button uses `className="sf-btn sf-btn--gradient sf-btn--md"` (or `--outline`). Hover, press, focus, and disabled live in CSS.
- Dialogs trap focus with `useFocusTrap` (`components/feedback/useFocusTrap.ts`). Success notes use `useToast()` from `components/feedback/Toast.tsx` (mounted in `AppShell`); errors stay inline next to the field.
- Empty states have one action. `EmptyState` takes `titleAs` (`h1`, `h2`, `h3`); use `h2` when it sits right under the page `h1`.
- Explain-back runs in focus mode: `components/learning/FocusMode.tsx` sets `data-focus` on `<html>` while mounted, which hides the sidebar and narrows the column. Drafts stay in `localStorage` under `skillflow-explain:<stageId>` until the stage is saved.
- Photos on dashboard pages: Progress shows each path's cover beside its mastery ring and Records as cards with the cover, a progress bar, and Transcript or Certificate buttons (`followedRecords` returns `image`). Notes shows the stage photo in the stage list and as a banner on the open stage (`LearnerNoteView.stageImage`, the path cover for practice notes; exports ignore it). Remote art stays `<img>`; local photos use `SkillImage`.
- Path page: cover hero with progress and one primary action, an "Up next" card, then `RoadmapStage` cards with a photo, a state chip (passed, up next, locked with the reason), and a cue. Lesson page: breadcrumbs, then a step-by-step wizard (`LessonWizard.tsx`, client) with one slide at a time: the intro (the stage title as `h1`, description, resource count, plan note), "Watch first" when there is a clip, one slide per remaining resource in the same order as before (kind, host, Optional, "What you will learn", Open in a new tab, the unavailable state), and "When you are ready". `CachedLesson.tsx` still loads the data and orders it (`orderedStageResources`, `arrange`) and renders each slide's content on the server; the wizard only moves between them. The stage photo (`stage.image`, else `skill.image`) is a banner on every slide; with neither, there is no banner. Above the slide: the kicker, the stage title as the page `h1` on every slide but the intro, "Step N of M", "N% through this stage" with a bar, 24px step dots labelled "Step N of M: <slide>", and one calm line with an emoji picked by progress (no points, no streak pressure). Back and Next sit in a sticky bar at the bottom (edge to edge under 640px); on the last slide Next becomes the one "Explain it back" link, so the slide itself does not repeat it. ←/→ and a sideways swipe also move, except while typing, on a video, or under a dialog. Transitions use framer-motion: `AnimatePresence` swaps slides with direction-aware variants (the old slide leaves in 140ms, the new one comes in from the side the learner is heading to in 240ms on the `--ease-out` curve, a plain fade for a restored step), and the progress bar, the encouragement line, and the Next or Explain it back button animate too. Reduced motion makes every change instant, but only after hydration (`useCalmMotion`), so the server render and the first client render match. Back and the right-hand button each sit in a `.sf-lwiz-cta` wrapper so the two halves of the phone bar are equal (a `.sf-btn` keeps its padding outside `flex-basis`). The slide region is `aria-live="polite"`, and focus moves to the new slide's heading (`data-slide-heading`). The step is kept per stage in `localStorage` under `skillflow-lesson-step:<stageId>` (read with `useSyncExternalStore`, so the server renders the intro). The locked and empty states have no wizard.
- Motion: `useCalmMotion` (`components/feedback/useCalmMotion.ts`) is the shared reduced-motion switch for the lesson wizard and the product tour; it turns on only after hydration so the server render and the first client render match. Tour styles are the `sf-tour-*` block at the end of `globals.css`; the tour sits at `z-index: 75`, under the recall card.
- Light mode gets its own treatment, not dark mode with the colours swapped (the "Light mode readability" block at the end of `globals.css`). Never fade a photo into `--bg-elevated` in light mode: that turns it into milky glass. Niche cards in light mode show a crisp photo band on top and a solid panel for the words (the card link joins the layout so long text grows the card, descriptions clamp at three lines); the Follow chip is solid white, and Following is the brand gradient. In light mode `--state-lock` is `#4e5a6c`, and `.sf-kicker` uses `--text-muted`, so small labels clear 4.5:1. Text on a photo needs its own dark shade under it in both themes. `Icon` sets `display` inline, so hide a decorative icon with `opacity`, not `display: none`. Check every new screen in light mode at 375px and desktop, not only in dark.
- Home's opening (the hero and the three "Get to know SkillFlow" tiles) must fit in the first screen on a laptop without scrolling: checked at 1024×700, 1280×640, 1366×657, 1536×730, and 1920×947. The "Home: the opening fits one screen" block in `globals.css` keeps it compact: tile banners are `clamp(68px, 10vh, 120px)`, tile text clamps at two lines, the tiles are always three across above 640px, and the Detox support state is a normal tile (never a full-width row). Do not add a fourth tile or taller copy there without re-checking those sizes.
- Sidebar order is by importance, in groups (`NAV` in `app/(app)/_components/AppShell.tsx`; a `section` on an item starts a small, `aria-hidden` group label): Learn (Home, Paths, Niches, Notes, Detox), Track (Progress, Analytics), Community (Clips, Open Source with Review for reviewers, Nearby), Account (Settings). It fits a laptop screen and scrolls on short ones. A new page goes into the group it belongs to, not at the end.
- Creating lives in the top bar, as on other platforms (`components/navigation/CreateActions.tsx`): Create content (primary, gradient, to `/creator`) and Submit a resource (secondary, outline, to `/submit`), 34px tall. Labels shorten to Create and Submit below 1280px; on a phone only a round Create button stays. The account menu also has Creator studio and Submit a resource, so both stay reachable on a phone. The top bar order is: menu (below 960px), search, create buttons, a running focus session, theme, bell, account.
- Page width: `--content-max` is 1200px and `--page-pad-x` 24px (16px on a phone); the top bar uses the same side padding, so search lines up with the content. Niches and the profile use the full column; reading pages (the legal documents, the career-fit report) keep a narrower measure on purpose.
- Dropdowns: every native `<select>` gets the app's picker through `appearance: base-select` (rounded themed panel, accent on the chosen option, a checkmark, the arrow turning when open; the "Dropdowns" block in `globals.css`). Browsers without it still get themed option colours, so a list never shows white text on white. Keep using a plain `<select>` with a `<label>`; do not build a custom listbox for a simple choice.
- Touch targets: a standalone text link or a small icon button gets an invisible 44px hit area with `.sf-hit` (or one of the selectors listed under "Touch targets" in `globals.css`). Step dots are 24px buttons.
- Images: `SkillImage` (`next/image`) for local files. Event art, contribution links, and Google avatars come from hosts nobody knows ahead of time, so they stay `<img>` with `loading="lazy"` or `decoding="async"` and a reserved box. Do not open `remotePatterns` to every host.
- Landing hero: `public/landing/posters/hero.jpg` paints first on every screen. The hero clips are `public/landing/hero-1.mp4` to `hero-5.mp4` (10.7 MB in all, compressed from 115 MB of 4K files). They mount only after hydration, at 960px and up, without reduced motion and without Save-Data. The feature images are real screens in `public/landing/shots/`.
- `html { scrollbar-gutter: stable; }` keeps streamed pages from shifting sideways. Do not remove it.
- `/privacy` and `/terms` are real documents built on `components/legal/LegalDocument.tsx` (short version, table of contents, numbered sections, contact card). The contact email and the "Last updated" date live in `lib/legal.ts`. They are static and prerender. They describe what the app actually collects and who handles it (Gemini or OpenAI, Stripe, OpenStreetMap, YouTube, Ticketmaster, SerpApi), Indian law and the DPDP Act 2023, and the age rule (18, or 13–17 with a parent's consent). When a feature changes what is collected, shared, or public, update `app/privacy/page.tsx` in the same change.
- `scripts/a11y-scan.js` can be pasted into the console on any page: overflow, unnamed controls, missing alt, unlabeled inputs, small targets, heading skips.
- `devIndicators` sits bottom-right in `next.config.ts`. A running dev server needs a restart to pick that up.

## Working rules

- Do not commit or push unless the user asks. After a piece of work, leave a commit message in the reply.
- Do not run the full seed.
- Do not research or rewrite pasted catalog text. Copy it. Omit note lines.
- If a link check fails, report the URL and the result. Do not replace it.
- Do not sign the browser out. Do not print `AUTH_SECRET` or passwords.
- When a screen, layout, or client flow changes, verify it in the browser before saying it is done.
- Decide the cache for every new page, section, and component. Content that is the same for every visitor uses `"use cache"`, `cacheLife("hours")`, and the `catalog` tag, and a write that changes it calls `invalidateCatalog()`. Session, progress, follow marks, streaks, and the account menu stay on the request. Do not call `auth()` inside a cached function.
- Every new page, section, and component must reflow at phone width. A grid uses one column under 640px and two under 960px unless the design is a single horizontal scroller. Put the mobile rule after the base grid rule so a later desktop rule does not win. Check 375px and desktop before saying a layout is done.
- Update `AGENTS.md`, `Project-roadmap.md`, and `README.md` when the product gains a capability those files do not mention. A new cache, a new path, a new lock rule, and a newly wired screen all belong there. Do not leave a new system only in code. Do not hand-edit `content/catalog/_review/`.
- The SkillFlow Assistant never writes the explanation of an explain-back idea from a stage the learner has not passed: `explainBackGuard` decides hint mode on the server, and hint mode also trims what the model sees. Do not move that check into the prompt only.
- The Premium filter for the assistant lives inside the SQL WHERE clause of both searches in `lib/assistant/retrieval.ts` (`(${premium} OR monetized = false)`). Never filter monetized chunks after the query. A unit test reads that file for both clauses.
- Assistant chats are not stored anywhere: no table, no log line with the message text. Only the per-day `ApiUsage` count is written.
- `EXPLAIN_MODEL_URL`, `EXPLAIN_MODEL_KEY`, and `ASSISTANT_EMBED_URL` are for the end-to-end stub and stay unset in production. All assistant SQL uses tagged-template `$queryRaw`/`$executeRaw` with bound values; never build SQL from strings.
- Every help article in `content/help/` states only what the code does. When a feature changes, change its article in the same commit and run `npm run assistant:index`.
